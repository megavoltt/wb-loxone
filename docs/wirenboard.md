# Wiren Board: режимы входов, события, шина

Мост работает с тем, что контроллер публикует в MQTT (`/devices/#`), и сам на
шину RS-485 не ходит. Поэтому скорость и надёжность по RS-485 определяет
драйвер `wb-mqtt-serial` и его настройки. Здесь — что на них влияет.

## Режим входа и события

Модули WB с прошивкой, поддерживающей **Fast Modbus**, умеют сами сообщать
драйверу об изменении входа — «события». Тогда драйвер узнаёт о нажатии за
единицы миллисекунд, не дожидаясь своего круга опроса.

Включает ли драйвер события для входа, зависит от **режима входа** в шаблоне
устройства. Например, у WB-MR6C и WB-MRM2-mini:

* режим **3** («Управление отключено, вход измеряет частоту») — событий нет,
  вход опрашивается по кругу;
* любой другой режим (0, 1, 2, 4, 6) — события включены.

Если вход должен работать только через Loxone и не трогать реле модуля, ставьте
режим **4 «Управлять по mapping-матрице»** и оставьте матрицу пустой (все
действия = 0). По поведению это то же, что режим 3, но с событиями.

### Как переключить

В веб-интерфейсе контроллера: **Настройки → Конфигурационные файлы → Настройка
драйвера serial-устройств** → нужный порт → устройство → группа нужного входа →
**Режим** = «Управлять по mapping-матрице». Проверьте, что для выходов в этой
группе выбрано «нет действия». Сохраните — драйвер перезапустится сам.

Названия пунктов зависят от версии прошивки. Если интерфейс отличается, то же
самое можно сделать в файле `/etc/wb-mqtt-serial.conf` — у устройства задать
параметры:

```json
"in2_mode": 4,
"in2_out1_actions": 0,
"in2_out2_actions": 0
```

и перезапустить драйвер: `systemctl restart wb-mqtt-serial`. Сначала сохраните
копию файла. На время перезапуска (несколько секунд) опрос всех устройств
шины останавливается.

### Как проверить, что события включились

```bash
journalctl -u wb-mqtt-serial --since "-2min" | grep "modbus:171"
```
```
INFO: [modbus] Init setup register "Mode": <modbus:171:holding: 10><-- 4 (0x4)
INFO: [serial client] Events are enabled for <modbus:171:discrete: 1>
INFO: [serial client] Events are enabled for <modbus:171:input: 33>
```

`discrete: N` — сам вход, `input: N` — его счётчик. Если строк
`Events are enabled` для входа нет, прошивка модуля не поддерживает события —
обновите её через веб-интерфейс контроллера.

## Шина RS-485

Драйвер опрашивает устройства порта по очереди. Время одного круга растёт с
числом устройств и каналов и сильно зависит от скорости.

Ориентиры для 9600 бод (это оценки, а не замер):

* один обмен с устройством — около 20–40 мс, то есть 30–40 обменов в секунду;
* модуль WB за круг — 3–6 обменов;
* отсюда 8–10 устройств на порт, если значения, которые не приходят событиями,
  должны обновляться примерно раз в секунду.

Что помогает, по убыванию пользы:

1. **События для входов и реле** (см. выше). Кнопки и реле тогда почти не
   зависят от длины круга, и на порту можно держать 15–20 устройств.
2. **Убрать ошибки на шине.** Каждый таймаут занимает шину на время ожидания
   ответа. Смотрите `journalctl -u wb-mqtt-serial` — строки
   `request timed out`, `invalid crc`, `failed to write`, повторяющиеся
   каждые несколько секунд.
3. **Распределить устройства по портам.** У контроллера два порта RS-485, они
   опрашиваются параллельно.
4. **Скорость 115200** — самый сильный рычаг, но все устройства порта должны
   её поддерживать. Сторонние устройства часто не поддерживают.
5. **Период опроса** (`read_period_ms`) для медленно меняющихся каналов —
   температура, влажность, энергия. Их можно читать раз в несколько секунд,
   освободив шину для остального.

Команды из Loxone драйвер отправляет вне очереди: реле переключается быстро
даже на загруженной шине.

## Что видно в MQTT

Мост показывает все устройства из `/devices/#`, включая системные (`system`,
`network`, `wb-adc`, `wb-gpio`…). Системные собраны внизу страницы.

Устройства zigbee2mqtt называются по IEEE-адресу (`0xa4c1…`). Задайте им
понятное «имя в Loxone» в интерфейсе моста.

Текстовые каналы, где лежат не числа (например, `action` кнопок Zigbee:
`single`, `double`), в Loxone не передаются: виртуальный вход UDP принимает
только числа. Такие каналы помечены «текст — не передаётся». Значения
`true`/`false` передаются как `1`/`0`.
