# Кнопки: одинарное, двойное, тройное и долгое нажатие

Кнопка, подключённая ко входу модуля Wiren Board (WB-MR6C, WB-MRM2-mini,
WB-MCM8, WB-M1W2 и других), приходит в Loxone двумя видами каналов:

| Канал в Loxone | Что приходит | Для чего |
|---|---|---|
| `Вход 1` | `1`, пока кнопка нажата; `0` после отпускания | удержание: диммирование, жалюзи «пока держу» |
| `Вход 1: одинарное` | импульс `1 → 0` | включить / выключить |
| `Вход 1: двойное` | импульс | сцена, «всё выключить» |
| `Вход 1: тройное` | импульс | ещё одна сцена |
| `Вход 1: долгое` | импульс, один раз за удержание | отдельное действие на долгое нажатие |

Каналы событий появляются автоматически у каждого входа, для которого в MQTT
есть пара `Input N` + `Input N counter`. Их выбирают и выгружают в шаблон так
же, как обычные каналы.

Импульс длится 150 мс (`pulse_ms`): сначала приходит `1`, затем `0`. На входе
блока Loxone это выглядит как короткое нажатие кнопки.

## Почему не отдать в Loxone просто вход

Loxone умеет сам различать двойное и долгое нажатие на цифровом входе.
Но для этого ему нужно видеть каждое нажатие и каждое отпускание вовремя. С
модулями на RS-485 это не так.

Драйвер `wb-mqtt-serial` опрашивает устройства шины по кругу. На 9600 бод и
десятке устройств круг занимает сотни миллисекунд, а то и секунду. Короткое
нажатие длится около 100–200 мс:

```
кнопка        ▁▁▁▁█████▁▁▁▁█████▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁   двойное нажатие
опрос шины    ▲                         ▲               ▲
вход в MQTT   0                         0               0   ← оба нажатия потеряны
```

Опрос может попасть между нажатиями, и Loxone не увидит ни одного. Или увидит
одно — и сочтёт двойное за одинарное.

## Как мост считает нажатия

У каждого входа модуля WB есть **аппаратный счётчик** импульсов
(`Input N counter`). Модуль увеличивает его сам, на каждом нажатии, независимо
от опроса. Счётчик не теряет нажатий: даже если опрос пропустил оба импульса,
он покажет «+2».

```
кнопка        ▁▁▁▁█████▁▁▁▁█████▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁
счётчик       100  101       102
опрос шины    ▲                         ▲
в MQTT        100                       102   ← +2 → двойное
```

Мост использует два источника:

* **число нажатий** — по приросту счётчика `Input N counter`;
* **удержание** — по состоянию входа `Input N`. Удержание длится дольше круга
  опроса, поэтому шина его видит.

Алгоритм:

1. Счётчик вырос — к серии добавляется столько нажатий, на сколько он вырос.
2. После каждого отпускания мост ждёт `click_ms` (по умолчанию 250 мс). Пришло
   ещё нажатие — серия продолжается. Не пришло — уходит событие: 1 нажатие →
   «одинарное», 2 → «двойное», 3 и больше → «тройное».
3. Кнопку держат дольше `long_ms` (600 мс) — сразу, не дожидаясь отпускания,
   уходит «долгое», и это нажатие больше не считается одинарным.
4. Состояние `Input N` всё время передаётся как есть — для диммирования.

### Не ждать без нужды

Пауза `click_ms` нужна, только чтобы отличить одинарное от двойного. Если более
длинная серия не нужна, мост её не ждёт. Учитываются только события, выбранные
для Loxone:

| Выбраны события | Одинарное уходит | Двойное уходит |
|---|---|---|
| одинарное | сразу при отпускании | — |
| одинарное + двойное | через `click_ms` после отпускания | сразу на втором нажатии |
| одинарное + двойное + тройное | через `click_ms` после отпускания | через `click_ms` после отпускания |

Вывод: не выбирайте лишнего. Если у кнопки только «включить/выключить» — выберите
одно «одинарное», и задержки на ожидание не будет совсем.

### Особые случаи

| Ситуация | Что делает мост |
|---|---|
| Опрос не увидел нажатие, только прирост счётчика | событие всё равно уходит |
| Оба нажатия двойного пришли в одном круге опроса (счётчик +2) | «двойное» |
| Счётчик пришёл уже после отпускания долгого нажатия | не считается одинарным |
| Вход замкнут в момент запуска службы (выключатель, датчик) | не считается долгим |
| Модуль перезагрузился, счётчик начался заново | прирост не засчитывается |
| Счётчик вырос больше чем на 20 сразу | считается мусором, пропускается |

Все эти случаи проверяются тестами: `python -m unittest discover -s tests`.

## Настройки

В веб-интерфейсе, блок «Подключение к Loxone»:

| Настройка | По умолчанию | Что меняет |
|---|---|---|
| Ожидание след. нажатия, мс (`click_ms`) | 250 | сколько ждать после отпускания следующего нажатия серии |
| Долгое нажатие от, мс (`long_ms`) | 600 | с какой длительности удержание считается долгим |

`pulse_ms` (150) и `button_log` (подробный журнал, выключен) меняются в файле
настроек `/mnt/data/etc/wb-loxone.json`, после правки — `systemctl restart wb-loxone`.

### Как подобрать `click_ms`

Это компромисс: чем меньше пауза, тем быстрее одинарное, но тем чаще медленное
двойное распадается на два одинарных.

Замер на живой кнопке: между отпусканием и вторым нажатием двойного у человека
проходит 150–200 мс. Отсюда 250 мс по умолчанию — с небольшим запасом. Если
кто-то в доме нажимает медленнее, поставьте 300–350.

**Пауза должна быть больше задержки шины.** Если вход опрашивается по кругу
(режим 3, см. ниже), второе нажатие может прийти позже паузы — и двойное
распадётся. Поэтому для кнопок нужен режим входа с событиями.

## Режим входа модуля — важно для скорости

У модулей WB у каждого входа есть параметр «Режим». От него зависит не только
то, управляет ли вход реле сам, но и **как драйвер узнаёт о нажатии**:

| Режим | Вход сам управляет реле | Как драйвер узнаёт о нажатии | Задержка |
|---|---|---|---|
| 0 — Кнопка, 1 — Выключатель… | да | событием от модуля | единицы–десятки мс |
| 3 — Управление отключено | нет | опросом по кругу | до круга опроса шины, бывает до 1 с |
| 4 — По mapping-матрице (матрица пустая) | нет | событием от модуля | единицы–десятки мс |

Если кнопка должна работать **только через Loxone**, ставьте режим **4 с пустой
матрицей**, а не 3. Поведение то же — вход не трогает реле. Но драйвер включает
для входа события (Fast Modbus) и узнаёт о нажатии сразу.

Замер на WB-MRM2-mini: в режиме 3 двойное приходило в Loxone с задержкой до
секунды, после перехода в режим 4 — через 1–30 мс после второго нажатия.

Как переключить и проверить, что события включились, — в
[wirenboard.md](wirenboard.md#режим-входа-и-события).

## Подключение в Loxone

Типичная схема для блока «Освещение» (Lighting Controller):

| Канал моста | Вход блока |
|---|---|
| `Вход 1: одинарное` | следующая сцена / вкл-выкл |
| `Вход 1: двойное` | сцена (например, «Всё выключено» или «Ярко») |
| `Вход 1: долгое` | ещё одна сцена |
| `Вход 1` (состояние) | вход диммирования, если нужно удержание |

Не подавайте на один блок одновременно `Вход 1` и события: блок сам начнёт
считать нажатия по входу и сработает дважды.

Подробнее — в [loxone.md](loxone.md).

## Отладка

Каждое событие пишется в журнал с миллисекундами:

```bash
journalctl -u wb-loxone -f
```
```
21:36:13.456 Нажатие: wb-mrm2-mini_171/Input 2#double
```

Чтобы видеть, когда приходят сами нажатия и счётчик, включите подробный журнал:
в `/mnt/data/etc/wb-loxone.json` поставьте `"button_log": true` и перезапустите
службу. Журнал пишется только для входов, у которых выбрано хотя бы одно событие:

```
21:37:01.760   вход wb-mrm2-mini_171/Input 2: нажата
21:37:01.763   вход wb-mrm2-mini_171/Input 2: счётчик 44 → 45
21:37:01.953   вход wb-mrm2-mini_171/Input 2: отпущена
21:37:02.386 Нажатие: wb-mrm2-mini_171/Input 2#click
```

Как читать:

* **«нажата» приходит позже, чем вы нажали** — задержка в шине: вход
  опрашивается по кругу. Проверьте режим входа (нужен 4, а не 3).
* **между «отпущена» и «Нажатие» — пауза `click_ms`** — это ожидание второго
  нажатия. Уберите лишние события у входа или уменьшите паузу.
* **«Нажатие» в журнале есть, а Loxone не реагирует** — проверьте IP
  Miniserver и порт UDP в настройках, адрес отправителя в блоке виртуального
  входа и что шаблон импортирован после выбора этого события.

После отладки выключите `button_log`: на загруженной системе журнал растёт быстро.
